# Algorithmic Trading Systems Research

**ประเภท:** โครงงานวิจัยและพัฒนาซอฟต์แวร์ด้วยตนเอง  
**เทคโนโลยี:** MQL5, MetaTrader 5 (MT5), Python  
**สภาพแวดล้อม:** ทดลองกับบัญชี MT5 Demo

## ทำไมถึงทำโปรเจกต์นี้

ต้องการศึกษาว่า **ระบบเทรดอัตโนมัติตัดสินใจ ส่งคำสั่ง และถูกทดสอบหรือแก้ข้อผิดพลาดอย่างเป็นระบบได้อย่างไร** ไม่ใช่ดูเพียงว่าออเดอร์ล่าสุดกำไรหรือไม่

กราฟระยะสั้นมีความผันผวนและสัญญาณรบกวนสูง บางจังหวะราคากลับตัว แต่บางจังหวะราคายังเคลื่อนไหวต่อ ทำให้ออเดอร์ที่ดูเหมือนเข้าถูกจุดก็ยังขาดทุนได้ จุดมุ่งหมายของงานจึงอยู่ที่การพัฒนาโปรแกรม การทดสอบและการวิเคราะห์สาเหตุ ไม่ได้อ้างว่า EA ทำกำไรได้แน่นอน

## สิ่งที่ลงมือทำ

- **พัฒนาและแก้ไขโปรแกรม MQL5:** ทดลองสร้างระบบส่งคำสั่งอัตโนมัติบน MT5 และปรับปรุงโค้ดเป็นรุ่นต่าง ๆ
- **วิเคราะห์ประวัติการส่งคำสั่ง:** ตรวจข้อมูลเข้า–ออก BUY/SELL และทบทวนสาเหตุของออเดอร์ที่ขาดทุน
- **เปรียบเทียบการทดลอง:** ตรวจว่าการเปลี่ยนแปลงเวอร์ชันส่งผลอย่างไร โดยไม่ตัดสินจากออเดอร์เพียงไม่กี่ไม้
- **ทดสอบความสามารถในการทำซ้ำ:** ศึกษาปัญหาที่ทำให้ Backtest เดิมรันซ้ำแล้วได้ผลต่างกัน และออกแบบการทดสอบที่ควบคุมเงื่อนไขมากขึ้น
- **วิเคราะห์ด้วย Python:** ใช้สคริปต์และสรุปข้อมูลเพื่อเปรียบเทียบผลการทดลอง
- **ใช้ AI ช่วยพัฒนา:** ให้ AI ช่วยตรวจโค้ด เสนอแนวทาง Debug และจัดเอกสาร พร้อมตรวจสอบผลด้วยการทดสอบ

## เหตุผลเชิงเทคนิคที่ใช้พัฒนา

| ปัญหาที่พบ | แนวทางการวิเคราะห์ |
|---|---|
| EA ออก BUY/SELL ผิดจังหวะ | ตรวจบริบทตลาดและประวัติคำสั่ง แล้วตั้งสมมติฐานเพื่อทดสอบ แทนการแก้จากออเดอร์เดียว |
| บางช่วงชนะหลายไม้ติดต่อกัน | ยังสรุปไม่ได้ว่าระบบแม่นยำตลอด ต้องประเมินช่วงเวลาที่หลากหลายและดูไม้ขาดทุนด้วย |
| Backtest รันซ้ำแล้วผลไม่ตรงกัน | ตรวจข้อมูล สภาพแวดล้อม และส่วนของโปรแกรมที่อาจอิงเวลาเครื่องหรือสถานะการรัน |
| กำไรต่อออเดอร์มีระยะสั้น | ต้องคำนึงถึง Spread, Slippage และต้นทุนการส่งคำสั่ง |
| EA รุ่นใหม่ดูเหมือนดีกว่าเดิม | เปรียบเทียบกับ Baseline และช่วงข้อมูลที่ไม่ได้ใช้ปรับกฎ เพื่อลดความเสี่ยงจาก Overfitting |
| ทดลองเพิ่มโมเดล Machine Learning | ประเมินว่าดีกว่าวิธีเดิมจริงหรือไม่ ไม่ใช่ดูเพียงค่า Accuracy/AUC |
